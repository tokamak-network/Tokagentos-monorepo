# Design: Simplify `tokagentos` CLI Onboarding

**Date:** 2026-06-18
**Package:** `@tokagent/tokagentos` (`packages/tokagentos`)
**Status:** Approved design — ready for implementation plan

---

## 1. Goal

Make the first-run experience of the public CLI trivially short. A new user
should reach a working project in **two decisions**: the project name and the
LLM provider (with that provider's API key folded into the same step). Remove
the features that add friction or are no longer wanted — the "create plugin"
starter template and the project `upgrade` path — and delete all code that
becomes dead as a result.

### Success criteria

1. `npx @tokagent/tokagentos@latest` (bare invocation) drops the user straight
   into project creation — no intermediate "what do you want to do?" menu.
2. The interactive create flow asks exactly two things: **project name**, then
   **LLM provider → API key** (plus LiteLLM model prompts only when LiteLLM is
   chosen). No template choice, no language choice, no final confirm.
3. The scaffolded app still boots fully configured (`.env` written,
   `~/.eliza/<project>.json` onboarding pre-completed) — parity with today.
4. The `plugin` starter template and the `upgrade` command no longer exist, and
   every function/type/test/doc that existed only to serve them is removed.
5. `bun run build`, `bun run typecheck`, `bun run lint`, and `vitest` pass with
   no references to deleted symbols.

### Non-goals

- No change to the `fullstack-app` template contents or its bundled runtime
  plugins (`templates/fullstack-app/plugins/plugin-*`).
- No change to the in-app plugin **installer/manager** (`packages/app-core`
  `plugins-cli.ts`, `plugin-installer.ts`) — that is product runtime, unrelated
  to the CLI "create plugin" starter.
- No rewrite of historical records under `docs/superpowers/plans|specs/*`.
- No new headless/CI creation path (see §7 risk).

## 2. Current State

### 2.1 Interactive prompts a fullstack-app user sees today

Bare `tokagentos` → `defaultAction` menu, then `create`:

| # | Prompt (source) | Disposition |
|---|-----------------|-------------|
| 1 | "What do you want to do?" — create / upgrade / info (`cli.ts` `defaultAction`) | **delete** |
| 2 | "Select a template:" — fullstack-app / plugin (`promptTemplateId`) | **delete** (one template remains) |
| 3 | "Select a language" (`promptLanguage`) | already skipped — fullstack is TS-only |
| 4 | "Project name:" (`promptProjectName`) | **keep → Step 1** |
| 5 | "Which LLM provider? (required)" (`promptLlmProvider`) | **keep → Step 2** |
| 6 | "Enter your API key (required)" (`promptApiKey`) | **keep**, folded into Step 2 |
| 6b | LiteLLM: base URL / small / large model (`promptLitellmExtras`) | keep, only when LiteLLM |
| 7 | "Create X?" confirm (`clack.confirm`) | **delete** (name prompt already validates dir) |

### 2.2 Relevant files

- `src/cli.ts` — commander wiring, `defaultAction` menu, all command/option registration, banner.
- `src/commands/create.ts` — the create flow, LLM provider list, `.env` writers, `preCompleteOnboarding`.
- `src/commands/upgrade.ts` — upgrade command (only consumer of project metadata + submodule-update machinery).
- `src/commands/info.ts` — lists templates.
- `src/commands/index.ts` — re-exports create/info/upgrade/version.
- `src/scaffold.ts` (~1872 lines) — mostly fullstack upstream submodule machinery (**keep**); a small plugin + upgrade + metadata slice (**delete**).
- `src/project-metadata.ts` — read/write `.tokagentos/template.json` (read only by `upgrade`).
- `src/types.ts` — template/option/value/metadata types.
- `templates/plugin/` — plugin starter template tree (TS / Python / Rust).
- `templates/fullstack-app/` — the product template (**keep**).
- `templates-manifest.json` — generated by `build.ts` from each `templates/<id>/template.json`.
- `scripts/packaged-smoke.mjs` — packaged smoke test; drives `create`/`upgrade` via flags.
- `scripts/sync-tokagent-plugins.mjs` — syncs fullstack bundled plugins (**keep, unrelated**).
- `scripts/agent-chat-smoke.mjs` — agent chat smoke (verify, likely unrelated to flagged create).

### 2.3 Verified dependency facts

- `readProjectMetadata` and the upgrade-only scaffold functions
  (`updateManagedFiles`, `updateGitSubmodule`, `createRenderedTempDir`) are
  imported **only** by `src/commands/upgrade.ts`.
- `writeProjectMetadata` / `buildMetadata` are used **only** by `create.ts` and
  `upgrade.ts`. With upgrade gone and metadata no longer read, both become dead.
- The manifest is generated by scanning `templates/<id>/template.json`; deleting
  `templates/plugin/` removes the plugin entry automatically.
- The `plugins/plugin-*` and `@elizaos/plugin-*` references in `scaffold.ts` are
  the fullstack app's **bundled** plugins — **not** the plugin starter template.

## 3. Target State

### 3.1 New interactive flow (bare `tokagentos`)

```
$ tokagentos
<banner>
◆ Project name:               ← Step 1
  my-app
◆ Which LLM provider?         ← Step 2
  OpenAI / Anthropic / Google / Groq / OpenRouter / LiteLLM / x402
◆ Enter your <provider> API key:   (part of Step 2; skipped for x402)
  ··········
  (LiteLLM only) base URL / small model / large model
→ scaffold → write .env → pre-complete onboarding → "Next steps"
```

No menu, no template choice, no language choice, no confirm. `version` / `-v` /
`--help` remain (commander built-ins + banner).

### 3.2 `create()` shape after the change

`create()` takes **no arguments** (interactive-only). Pseudocode:

```
export async function create(): Promise<void> {
  clack.intro(" tokagentOS ")
  const template   = getTemplateById("fullstack-app")   // the only template
  const language   = template.languages[0]              // "typescript"
  const name       = await promptProjectName()          // Step 1
  const values     = buildFullstackTemplateValues(name)
  const provider   = await promptLlmProvider()          // Step 2
  const apiKey     = provider.envVar ? await promptApiKey(provider) : undefined
  const litellm    = provider.id === "litellm" ? await promptLitellmExtras() : undefined
  // scaffold (always init upstream — no skip flag)
  renderTemplateTree(...)
  resolveTemplateUpstream + initializeGitSubmodule + hydrateGitSubmoduleWorkspace
  ensureEnvFromExample(dest)
  if (apiKey) { writeLlmEnvFile(...); writeLlmExtraEnv(litellm + openrouter defaults); preCompleteOnboarding(...) }
  clack.note(nextSteps); clack.outro(...)
}
```

`promptProjectName` / `promptLlmProvider` / `promptApiKey` / `promptLitellmExtras`
lose their flag/`--yes` branches and always prompt. The provider list, `.env`
writers (`ensureEnvFromExample`, `writeLlmEnvFile`, `writeLlmExtraEnv`), and
`preCompleteOnboarding` are unchanged.

`getNextSteps` simplifies: no `--skip-upstream` branch, so it returns
`cd <dir>` → `bun install` → `bun run dev`.

## 4. Deletions (dead-code teardown)

### 4.1 Plugin starter template

- **Delete** `templates/plugin/` (entire tree) → manifest regenerates with only `fullstack-app`.
- `src/scaffold.ts`: delete `buildPluginTemplateValues`, `getPluginReplacementEntries`; in `getTemplateReplacementEntries` drop the `templateId === "plugin"` branch (or replace the call site with `getFullstackReplacementEntries` directly).
- `src/commands/create.ts`: delete `promptPluginValues`, the plugin icon in `TEMPLATE_ICONS`, the `template.id === "plugin"` name-prefix and value-building branches.
- `src/types.ts`: delete `PluginTemplateValues`; narrow `TemplateId` to `"fullstack-app"`.
- Remove plugin-only CLI flags `--description`, `--github-username`, `--repo-url` (subsumed by §4.3).

### 4.2 Upgrade command + metadata (full teardown)

- **Delete** `src/commands/upgrade.ts`.
- **Delete** `src/project-metadata.ts` (read + write + path helpers).
- `src/scaffold.ts`: delete `updateManagedFiles`, `updateGitSubmodule`, `createRenderedTempDir`, `buildMetadata`.
- `src/commands/create.ts`: remove the `writeProjectMetadata(...)` call (no reader remains) and the `--skip-upstream` branch — upstream is **always** initialized.
- `src/types.ts`: delete `UpgradeOptions`, `ProjectTemplateMetadata`.
- Remove `.tokagentos/template.json` as a concept (nothing writes or reads it).

### 4.3 Flags, menu, and `info` (interactive-only)

- `src/cli.ts`: remove `defaultAction` and its menu; `program.action(() => create())` so bare invocation creates. Remove the `upgrade` and `info` command registrations. Keep `-v`/`--version` and `--help`; **drop the redundant `version` subcommand** (the `-v` flag covers it) — and delete `src/commands/version.ts`. Remove **all** `create` options and the `[name]` argument.
- `src/commands/index.ts`: export only `create`.
- **Delete** `src/commands/info.ts`; `src/types.ts`: delete `InfoOptions`.
- `src/types.ts`: reduce `CreateOptions` to empty/remove it; `create()` is argument-free.
- Keep the banner and `--help`/`-v`.

### 4.4 Net effect on `scaffold.ts` and `types.ts`

`scaffold.ts` keeps **all** fullstack upstream machinery
(`resolveTemplateUpstream`, `initializeGitSubmodule`,
`hydrateGitSubmoduleWorkspace`, `ensurePackageJsonWorkspaces`,
`pruneUpstream*`, `rewriteUpstreamWorkspaceDeps`,
`applyUpstreamSurgicalPatches`, `ensureUpstreamCompatibilityFiles`,
`renderTemplateTree`, `resolveTemplateSourceDir`, `toDisplayName`,
`buildFullstackTemplateValues`, `getFullstackReplacementEntries`, …) and loses
only the plugin + upgrade + metadata functions. `types.ts` keeps
`TemplateDefinition`, `TemplateUpstream`, `TemplatesManifest`,
`FullstackTemplateValues`.

## 5. Tests

Because the CLI is now interactive-only, **no flag-driven headless creation
exists**. Test strategy:

- **`scripts/packaged-smoke.mjs`** — rewrite to a single fullstack path that
  exercises the scaffold **at the function level** (call the underlying
  create/scaffold logic with fixed inputs), not the clack prompt UI. Remove the
  plugin case, both `upgrade` cases, and the `--skip-upstream` case.
- **`src/__tests__/create.test.ts`** — currently passes flags
  (`yes`, `llm`, `apiKey`, `template`). Rewrite to either (a) mock `@clack/prompts`
  to feed name/provider/key, or (b) move the `.env`-content assertions
  (OpenRouter defaults, LiteLLM keys) to direct tests of `writeLlmEnvFile` /
  `writeLlmExtraEnv`. Preference: (b) for the env assertions + a thin prompt-mock
  test for the two-step flow.
- **`src/__tests__/scaffold.test.ts`** — drop `buildPluginTemplateValues` /
  `getPluginReplacementEntries` cases; keep fullstack replacement-entry tests.
- **`src/__tests__/types.test.ts`** — update for narrowed `TemplateId` and
  removed types.
- **`src/__tests__/manifest.test.ts`** — assert exactly one template
  (`fullstack-app`); drop plugin expectations.
- **`src/__tests__/gitmodules.test.ts`, `scaffold-patches.test.ts`** — fullstack
  upstream machinery; expected unaffected. Verify they don't reference plugin/upgrade.
- **`scripts/agent-chat-smoke.mjs`** — verify it doesn't depend on flagged
  `create`; update only if it does.

## 6. Docs

- `packages/tokagentos/README.md` — rewrite to the two-step flow; remove the
  `### tokagentos create` plugin examples, the `### tokagentos upgrade` section,
  and `### info`.
- `packages/tokagentos/scaffold-patches/README.md` — drop the "If a user later
  runs `tokagentos upgrade`…" line (or restate as "fresh scaffolds only").
- Root `README.md` — minimal touch-ups only if it names the plugin template or
  upgrade in the onboarding context (architecture sections stay).
- `package.json` `description` — "tokagentOS CLI - Create and upgrade tokagentOS
  project templates" → drop "and upgrade".
- Historical `docs/superpowers/plans|specs/*` — **not** modified.

## 7. Risks & Trade-offs

1. **No headless/CI create path.** Consequence of "keep API key in CLI" +
   "interactive-only". Accepted: automated scaffolding, if ever needed, tests at
   the scaffold-function layer (as the rewritten smoke test does), not the CLI.
2. **No upgrade path for existing scaffolds.** Intended. The fullstack upstream
   submodule is pinned to a commit, so fresh scaffolds remain reproducible; users
   wanting newer upstream re-scaffold.
3. **Smoke coverage shifts** from "spawn the published binary with flags" to
   "exercise the scaffold function". Slightly less end-to-end (doesn't prove the
   bin shebang/arg parsing), but far less brittle and matches the new reality.
   `--help`/`-v` smoke can still spawn the bin to cover arg parsing.
